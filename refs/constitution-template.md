# 宪法（Constitution）

> **本文件中的元原则、条款体系与修宪程序需经人工审议后修改，不接受 Agent 自主变更。**
>
> 本文件是知识库 Agent 维护系统的设计参考。**不是运行时依赖**——Agent 运行时操作准则在 `AGENTS.md`。本文件不被 agent 自动加载，日常维护无需阅读。当需要理解某条规则的设计意图、做内容放置决策时参阅。

---

## 第零部 · 宪法的目的

本仓库是一个持续增长的个人知识库，目标是：

- **永无死角**：记过一次的内容一定能找回来
- **不重复建设**：新写内容前能知道自己是否写过类似
- **自维护**：索引、摘要、关联不依赖人工维护
- **知识复利**：笔记间的关联随时间自然密化

---

## 第一部 · 三条元原则

### 元原则 I · Occam's Razor（如无必要，勿增实体）
不要引入多余的文件、目录、字段、概念。每增加一个结构体必须回答"它解决什么问题"。警惕"为统一而统一的抽象层、预判未来需求的分类、解决一次性问题的永久机制"。

### 元原则 II · Separation of Authorship（谁写的谁看）
- **用户的领地**：分类目录下的 `.md` 原文、用户手写的 tag/双链
- **Agent 的领地**：`.meta/` 和 `.index/` 下的所有内容
- **可追溯性**：Agent 产物必须在 frontmatter 携带 `agent`（宿主框架）、`model`、`generated_at`；技术类笔记另加 `applies`（universal / agent-bound / mixed）声明框架适用性——不同宿主框架的工具链与运行环境不同，跨框架复用经验前以此判断可信度

### 元原则 III · Bitter Lesson（通用方法优于硬编码先验）
优先调用 embedding / LLM / 语义检索（通用 meta-method）；谨慎引入硬编码分类、关键词规则。

## 第二部 · 持久性四型（内容放置裁判）

| 型 | 定义 | 更新模式 | 数据丢失风险 |
|---|---|---|---|
| 快照型 | 每次生成时全量覆盖 | 脚本完整重写 | 无——可从原文重建 |
| 追加型 | 仅追加新内容，有界分片 | 尾部追加 | 无 |
| 派生型 | 可从源数据完整重建 | 增量或全量 | 无——gitignored |
| 持久型 | 手动维护的长期记录 | 编辑更新 | 有——不可重建 |

> 前三型覆盖 Agent 自动产物；第四型覆盖用户与 Agent 共同维护的文件。需要跨维护周期存活的内容必须放在持久型文件中。

**持久型文件清单（权威列表）**：`AGENTS.md` / `docs/CONSTITUTION.md` / `docs/TAXONOMY.md` / `docs/CHANGELOG.md` / `docs/plans/` / `.meta/rules/` / `.meta/memory/` / `.meta/converge/`（仓库自行新增的持久目录按此型对待）

## 第三部 · 知识库治理体系（多轴门控）

> 详细设计见本 bundle [refs/governance-multi-axis.md](governance-multi-axis.md)。

治理体系下事务按**门控轴**切分，轴集合开放可扩展。当前 3 条：

**①编辑门控轴**（按"改动触发的审批强度"）
- **治理文档**（对 Agent 行为有规范性约束力；机械边界 = `.meta/governed-files.txt`）→ 改动走 ultraverge（≥3 独立 reviewer、≥2 lineage、≥1 fresh-context）
- **持久型文件**（手动维护、不可重建）→ 改动需人工审议

**②从机访问轴**（按"哪台 host 可写"）
- **从机禁改清单** → 从机写入拒绝（仅 PRIMARY_HOST 可写维护层）

**③隐私读轴**（按"内容敏感度限制读取"）
- **隐私目录**（Phase 0 嗅探 + category-privacy.md）→ 禁 Read/Grep

**计划质量控制**采用同一 plan 生命周期：`起草 plan → converge 收敛 → 按授权执行 → fresh verifier 验收 → 用户确认后 done`。执行前收敛由 converge SKILL 承担（`.meta/converge/README.md` 绑定本地路径），执行后验收由 fresh verifier 承担，证据写入 plan。

> 消歧：「治理体系」指受门控的文件/门控轴集合；区别于 converge 判断动作模块（执行前收敛 + 执行后 fresh review 的单一生命周期）。

## 第四部 · 写作约束

修宪后的文档只呈现当前体系，不保留历史过渡态表述（"原来""以前是 X 现在改为 Y"等）。历史追溯走 git + CHANGELOG。此约束适用于持久型文件下的所有文档。

---

## 第五部 · 修宪程序

元原则修订、条款体系重组、作者分离边界重定义按修宪程序（人工审议 + 多 agent 评议）更新本文件。日常操作细则的演化只发生在 `AGENTS.md`。
