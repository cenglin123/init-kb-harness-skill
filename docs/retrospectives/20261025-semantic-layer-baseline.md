# 语义层基线化改造 · 治理复盘（2026-10-25）

> 对象：init-kb-harness 技能仓库及由它初始化的知识库。
> 范围：把 embedding 从「可选云端」改为「默认本地基线」，并把 LLM 层收敛为可选增强。
> 记录目的：留下决策依据、评审证据、缺陷根因与完成边界，供后续维护者复核。

---

## 1. 目标的确立过程

| 阶段 | 用户输入 | 决策结果 |
|---|---|---|
| 起点 | 「embedding 能不能换成本地轻量小模型？」 | 允许本地化，但尚未定默认 |
| 对照 | 「Hermes 怎么解决？」 | Hermes 用 FTS5 + agent 多轮、不预计算向量；本项目的 office 语料场景不同，语义召回仍需保留 |
| 成本 | 「比调 API 麻烦很多」 | 放弃「队列 + 并行子代理做摘要」方案 |
| 方向 | 「embedding 必须；LLM API 不需要就不要」 | **语义层是基础能力，LLM 层默认关闭** |
| 约束 | 「仓库不放模型和依赖；套件要自包含；效率优先 + office 超时」 | 内置模型 + 离线套装 + 流式并发 + 子进程超时 |

治理含义：**默认值的变更由用户拍板；实现路径、失败语义、评审方式由执行方负责**。本复盘按此边界记录。

## 2. 决策记录（含被否决项）

| 决策 | 采纳 | 依据 | 被否决的替代 |
|---|---|---|---|
| 默认嵌入来源 | 内置 `bge-small-zh-v1.5`（fastembed，512 维 / 450 字） | 零 API、可离线、升级前始终有可用嵌入 | 仅云端（违背"必须有基本嵌入"）；仅 Ollama（新机无服务） |
| 嵌入客户端 | 单一 OpenAI 兼容 `/embeddings` 客户端 + 内置模型兜底 | 一份代码覆盖 Ollama/vLLM/智谱/OpenAI | 每厂商一个类；运行时多后端枚举 |
| 切换语义 | 配置变化拒绝增量，`embed.py --full` 显式重建；staging + 单事务换表 | 派生数据可重建，但绝不能"先毁后失败" | 自动清库；按配置自动换代 |
| 语义关联（links） | 纯余弦 + wikilink，无 LLM | 与 LLM 层解耦，lite 也有 semantic 边 | 继续由 summarize（LLM）生成 |
| LLM 层 | `HARNESS_MODE=full` + key；默认关 | 摘要不参与排序，只影响可读性 | 默认开；用 agent 代劳批处理 |
| 批处理 | 脚本并行 + 流式写库 | 上下文与成本可控，可无人值守 | 队列 + 子代理 + 租约（复杂度过高） |
| 摘要参与召回 | 不做 | 无失败样本支撑，违反 Occam | 摘要进 BM25/精确召回入口 |
| 新鲜度 | content hash + 模型 + 阈值指纹 | 确定、可复现 | mtime（会把正常未维护误判为陈旧） |
| 派生件入库 | 二进制派生件移出 git | 每次维护数十 MB 二进制会撑爆历史 | 全部入库；git-lfs |

## 3. 评审治理：三轮独立评议

每轮均为**全新上下文的独立 reviewer、只读、单轮 verdict**；执行方只做编排、复核事实与修复，不参与打分。

| 轮次 | 结论 | 关键阻断（经复核） | 处置 |
|---|---|---|---|
| 第 1 轮 | 阻断 | `auto` 从 DB 反推后端；坏 key 先清库后失败且 exit 0；维度是"声明"非实测 | 删除 DB 反推；改为探针 + staging + 单事务换表 |
| 第 2 轮 | 阻断 | BM25 损坏被当"无结果"；GBK 笔记卡死 `--full`；同名笔记 semantic 边指错；语义失败仍 exit 0；office 无原子写 | 引入 `None`/`[]` 区分；不可读跳过 + 报告；路径式链接；exit 3；原子写 |
| 第 3 轮 | 一票可执行 / 一票阻断 | `.env:PRIVACY_DIRS` 不生效（隐私目录被嵌入）；office 提取件不算用户语料 | 配置统一走 `ENV`；语料口径纳入 office；55 测试收口 |

治理要点：

1. **阻断优先用"删除"解决**：`auto` 反推、自动清库、四态后端枚举都是被删掉的，而不是打补丁。
2. **每条阻断必须可复现**：reviewer 给出命令与输出，执行方独立复现后才修。
3. **一票否决有效**：第 3 轮一位 reviewer 判可执行，另一位判阻断；后者的事实成立，因此不宣布通过。

## 4. 缺陷复盘（根因与预防）

| 缺陷 | 根因 | 修复 | 预防 |
|---|---|---|---|
| 坏 key 清空向量并报成功 | 清库发生在鉴权/推理之前 | 探针 → staging → 全成功才换表 | 任何"销毁型"操作前必须有可验证的前置成功 |
| lite 停不掉云端 | 从派生 DB 反推配置 | 配置只读 `.env`；库只做一致性校验 | 派生数据不得作为配置源 |
| `--check` 假阴性 | 索引损坏/层不可用被折叠成 `[]` | `None` 表示不可用，exit 2；BM25 损坏同样报错 | "不可用"与"无命中"必须是两种返回 |
| 隐私目录失效 | 代码读 `os.environ`，`.env` 只进 `ENV` | 统一 `ENV`（shell 仍可覆盖）+ 隐私生效测试 | `.env` 每个键都要有生效测试 |
| 升级死锁 | 永久不可读文件被计入"失败" | 登记 `embed-skipped.md` 后跳过 | 区分"本轮失败"与"永久不可读" |
| 门槛形同虚设 | maintain 只信 embed 退出码 | 追加"用户语料向量 > 0"校验；exit 3；health 覆盖率 | 验收条件要检查产物，不只看返回码 |
